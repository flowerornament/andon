# Coverage is a ledger fact

## Why

Three acceptance rounds found the same defect at different sites: a board or
scorecard said "0", "no landing" or "0.0 h" where the ledger simply held no
data. A past instant before the landing source's horizon said a seat had not
landed; a window before it said `lands 0`; an unreadable transcript made a
seat's effort 0.0. Each was fixed where it was found, and the next round found
another. The cause is one: the ledger recorded facts but not where it was
able to look, so every fold had to guess, and guessed "nothing happened".

The founding design's invariant is "if a fact cannot be derived from an
artifact, it is not on the board". Absence is a fact too, and it can be
derived only where the ledger covers. This amends §4 for every adapter,
including the ones not yet written.

## The contract

A new core kind, `coverage`, records what a source let andon see.

```
{ "kind": "coverage",
  "t": start of the span,          # UTC
  "t_end": end of the span | null, # null: through the ledger's end
  "actor": a seat's label | null,  # null: every seat
  "outcome": "pass" | "fail",      # pass: read; fail: could not be read
  "attrs": { "covers": [kinds],    # the kinds the span vouches for
             "reason": text,       # for fail: what could not be read, why
             "adapter": name },
  "source": the store }
```

- **A pass span** says: for these kinds, for this seat or every seat, every
  fact between `t` and `t_end` that the store holds is in the ledger. A live
  adapter ends its span at the instant it read (capture time); a span with no
  end is open.
- **A fail event (a gap)** says: this store held facts of these kinds that
  could not be read (an unreadable transcript, a receipt that is not JSON).
  It covers nothing; while it stands, the kinds it names are not fully known
  for its seat (or every seat).
- **Every adapter emits coverage**: the core adapters for what they read
  (jj and git from `since` for landings and change starts; bd for its items
  and comments; Ferry from its oldest kept receipt; hail from `since`;
  sessions from `since`, with a gap per unreadable transcript). An external
  adapter emits its own; without coverage, its kinds are not known.

## The rule

Every gauge names the kinds it reads, and is known for a seat over a window
only if every one of those kinds is covered for that seat over the whole
window, with no gap standing. Otherwise the gauge is **unknown**, and says
why: it is never rendered 0, "none" or "no landing".

| gauge | kinds | over |
|---|---|---|
| landings, last landing | land | the window |
| runs, pass rate, failures, failures without a reason | run | the window |
| runs per landing | run, land | the window |
| runs since landing; "N runs and no landing since D" | run, land | D to the instant |
| "no landing in Nd" | land | the quiet span to the instant |
| gate runs, land gate median | gate_run | the window |
| verdicts, last verdict, review median | verdict (and land) | the window |
| change start → landing | land, commit | the window |
| messages sent, received, naming a goal, decisions without one; hub | message | the window |
| items created, closed, created/closed | create, close | the window |
| open, unowned, goals held, WIP | create, claim, close | all time to the instant |
| findings | other:comment | the claim to the instant |
| active hours, budget spent | session_active | the window, or the claim to the instant |
| landing → session seen | land, session_active | the window |

In JSON an unknown gauge is `{"unknown": "<reason>"}` in place of its value;
in text it is `?`, with the reasons listed beneath the table.

`asof` keeps every coverage event, whatever its instant, with spans clipped to
the instant: coverage describes the ledger, not the past. So a past instant
before a source's horizon is unknown with the horizon named, not "no landing".

## What does not change

Facts are still facts: a landing in the ledger is shown whether or not its
span is covered. Coverage decides only what absence and totals may claim.
The checks keep their own rule (a refusal needs the fact it refuses on); a
tracker that is not covered makes `check commit` unable to decide, exit 2.

## Amendment: the class made unrepresentable (2026-10-14, round four)

Round four of the reviewer's acceptance found four more escapes of one class.
Since-land was a known 0 when its count origin lay after the instant (C1).
Unreadable directories were skipped while full coverage was claimed (C4).
bd's export vouched for claims and closes since 1970 (C7). A goal's budget
spent was masked in text but not in JSON (C8). Each was a site the masks
missed. The fix replaces masks with a type, a registry and a property.

**One type.** Every gauge the scorecard and board print is a
`Gauge<T>`: `Known(v)` or `Unknown(reason)` (`src/fold/gauge.rs`). The output
structs hold gauges, not counts. JSON serializes an unknown gauge as
`{"unknown": reason}`; text prints `?`, through `Gauge::cell`. Flags read only
known gauges; the reasons footer is read off the serialized output. No
renderer can reach a bare count, so a 0 where the ledger could not look
cannot be printed. A gauge holding gauges (the goals held, each with its
budget spent) is unknown as a whole or known with each inner gauge decided
on its own.

**One registry.** A gauge is built only by `Gauger::gauge(path, …)`, from
its registered `Spec`: the kinds it reads, kinds read only for one seat
(verdicts reach a seat through the reviewed commit), its span, and the gauges
it is computed over (`via`: findings are counted over the goals held). An
unregistered path is unknown. Spans:

- **Window**: each kind covered over the window.
- **Origin**: each kind covered from an origin the fold supplies (the last
  landing, the first claim) to the instant. An origin after the instant, or
  none, makes the gauge unknown (C1). A last landing is known when nothing
  after it went unread; "no landing ever" only when all history was read.
- **State**: the state at the instant (goals held, WIP, open, unowned): each
  kind read over all history, or a current-state source read at the instant.

A coverage check over an instant (a zero-length span) passes only where a
span holds that instant. The walk used to pass any zero-length span by
default, which was C1's root one level down.

**Coverage is what each adapter read.** No adapter asserts coverage it did not
read:

- Every directory an adapter lists goes through one recorder
  (`adapters::Reads`). A directory that exists but cannot be listed, a file
  that cannot be read, and a file that is not a record of the kind (a receipt
  without `started_ms`, a hail file without a sender) each become a gap
  naming the path (C4). A missing path, or a file a wildcard matched, is
  absent, not unreadable.
- Each adapter's span starts where its read starts (its `since`, the oldest
  receipt) and ends at the capture instant. The CLI reads the clock once,
  before the sources, and every adapter stamps that instant
  (`Config::capture`).
- Every coverage event carries `attrs.adapter`.

**bd is current state (C7).** An export keeps each goal's creation and
comments with their times, so it covers `create` and `other:comment` as
history. It does not keep claims released or goals reopened: on the originating
project's tracker, 232 goals were closed more than once. So it covers claims and closes
only as `state:claim` and `state:close`, at the capture instant, and only
when the export is whole (no `since`). The board at the capture instant
knows the goals held; `asof` at an earlier instant, the scorecard's closes and
created/closed, and the state at a past window's end are unknown.

bd's `events` table holds the history, but the originating project's rows mix time zones.
Rows up to about 2026-10-06 are local time stored as UTC, 7 h ahead of the
issue's own `closed_at`; later rows agree with it. No single correction
holds. andon does not read the table until bd's times are consistent; a kept
ledger, captured over time, is how a project keeps tracker history today.

**The hook's change line** counts facts since the last turn. Where a kind it
counts is read by some source but not over that whole span, the line says so:
`not fully read since then: landings`. A kind no source reads is a fact of the
configuration, shown as `?` on the board, not news each turn (C3).

**Two properties over the registry** (`tests/coverage.rs`), so a new gauge is
covered by construction:

1. *Faults reach every reader.* For each kind, its source is absent, its
   horizon moves past the window, or it names a gap. Every gauge whose
   registration reads that kind (directly, per seat, or through `via`) must
   be unknown, in the scorecard and on the board. Every gauge either output
   can print must be registered.
2. *Registrations name what values depend on.* For each kind, its facts are
   left out while its source still covers it. Every gauge whose value moves
   must register that kind. This half reads the folds, not the registry, so a
   gauge that under-declares is caught. It found two: the review flow reads
   change starts, and findings depend on the goals held.

Per-adapter tests (`tests/horizons.rs`) pin each adapter's coverage start to
what it reads, and each unreadable path to a gap.

The table above gains: review median reads land, verdict and commit;
findings and budget spent are unknown with the goals held; open, unowned,
goals held and WIP are state at the instant.

## Amendment: round five (2026-10-14)

**A read starts no later than its coverage.** jj and git read a date-only
`since` in local time; git also adds the current time of day. So jj's read
began at 07:00Z in PDT, and git's at an hour that moved through the day,
while coverage was claimed from 00:00Z (D1, D2). Both now filter from a UTC
instant 48 h before `since` (`time::read_from`), as jj's operation log
already did. A commit made before `since` that landed after it is still
read. The tests run the binary under several `TZ`s and check what was read:
every landing after `since`, not only where coverage starts.

**Sealed.** `Gauge` is a struct over a private state. Outside
`fold/gauge.rs` a gauge is read, never made; the only constructors are
`Gauger::gauge` and `Gauger::over`. `over` builds a gauge computed over
another gauge's value, and its spec must name that gauge in `via`.

**A census of every cell.** The registry properties take their instances
from the outputs themselves. Every JSON leaf of the scorecard and the board
lies inside a registered gauge, or is declared metadata (`METADATA` in
`tests/coverage.rs`: schema, the window, the instant, a row's seat and
flags). A bare field such as `spawns: usize` is a stray and fails. A spec
that reads no kind must be declared (`KINDLESS`; today only wall-clock
budget, which is unknown with the goals held). A goal's last-work time and
a row's `runs_from` are internal keys, not gauges, so they are not output.

**Smaller rules.**

- The unattributed card reads what a seat's card reads. Whether a verdict
  can be attributed depends on change starts, so its seat kinds apply (D7).
- The hook lists claims and closes only where some source reads them as
  history. From a current-state export they are not changes since the last
  turn (D5).
- An unknown reason names the source: `closes are read only as current
  state, not history (bd export …)`. A count with no start in the ledger
  gives the horizon of what it reads (D6).
- A hail outbox copy takes its sender from the seat directory it sits in
  (D8).

## Amendment: round six (2026-10-14)

The reviewer accepted the v0.1.0 candidate. Three of its findings landed before
the tag:

- **A text census** (E1). With no coverage at all, every data cell the
  scorecard and board print as text is `?`, and their summary lines carry no
  number. A column computed outside the gauges fails, even one kept out of
  JSON.
- **The read margin, tested** (E2). A change committed before `since` and
  put on the trunk after it is read as a landing after `since`. With no
  margin, the test fails.
- **A reason names the capture** (E3). `read only until` gives the latest
  instant a span reached, not the instant asked for.

E4 stays as it is. One landing in 233 is timed by its commit, 27 minutes
before its publish, under the batch rule.

## Amendment: the adapter contract (2026-10-19, andon-azp)

A review on 2026-10-14 found six places where an adapter dropped input
silently and still claimed coverage. Each is now a gap, or the read is
refused:

- a bd comment that starts as a verdict but is not JSON;
- a bd comment, or a GitHub issue, comment or run, with no time;
- a GitHub snapshot list that is missing, unreadable or not JSON;
- an unreadable hail header in another project's seat, or a message with
  no time;
- a transcript read error, a malformed line before the last, or a turn
  time that does not parse;
- an op-heads entry jj cannot list.

GitHub issue events are read to the last page.

**One policy.** Ferry's is the one kept: one unreadable item, one gap,
naming the item, and the rest is read. A tool whose whole output is
malformed (`bd export`, `jj log`) still refuses the read and names the
adapter. `tests/contract.rs` feeds every adapter in `adapters::CORE`, and
an external adapter, a corrupt or unreadable input. It asserts that the
affected kinds come back uncovered, or that the read is refused. A new
adapter joins with a fixture.

**A gap at an instant.** Until now a gap stood over every span, which
was right for a source whose facts have no known time. A fact whose time
the store records but whose content cannot be read is different: it is
unknown at that instant. `event::gap_at` marks such a gap with
`t_end == t`, a span of one instant, as a current-state read is. It
stands only over the spans that hold that instant. This matters because
bd comments cannot be edited. One prose verdict (`Critic-Verdict: GO,
...`) would otherwise make every verdict unknown, for every seat,
forever. With the instant gap, a later known verdict supersedes it, and a
window that does not hold it is unaffected.

**Smaller fixes.**

- jj no longer claims `freeze`, which it never emits.
- jj reads its operation from the store's op heads (the newest, when
  writers diverged) instead of matching jj's error text.
- A budget with no amount renders in the unit it was counted in.
- Fix lines name the tracker the config reads (`seat::Tracker`). A
  project with neither bd nor GitHub is never told to run bd.
